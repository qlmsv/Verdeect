# Статус реализации

M0.1, 2026-09-14. Development foundation. Не production и не готовый SaaS.

## Работает и проверено локально

Platform API: организации, членство, сессии, CSRF/Origin, матрица разрешений и аудит изменения metering-grant.

Metering API: создание приборов, добавление показаний, история, проверки организации, точное десятичное значение, идемпотентность. Два процесса проверены через настоящий HTTP.

SDK: проверка пространства маршрутов, жизненный цикл, отмена устаревшего mount, отказ от смены организации без unmount. Тесты используют синтетические DOM-объекты.

## Написано, но не принято сквозными тестами

Svelte-навбар, страницы входа/счётчиков/доступов; преобразование upstream-маршрутов; OIDC-контроллер; Dockerfile/Compose; React fixture. Наличие исходников не означает работающий браузерный сценарий.

## Блокеры следующего этапа

1. Получить закреплённый upstream, собрать реальный frontend, проверить root layout и вложенные маршруты, CSS, штатные чат/файлы/streaming в браузере. Сейчас тестируется только синтетический репозиторий.
2. Подключить живой Keycloak, общий вход с OpenWebUI, назначение/отзыв прав, технические редиректы и глобальный выход. Проверить уже открытую вкладку и активные WS/SSE. `chat.use` пока не обеспечен платформой для прямого доступа в OpenWebUI.
3. Заменить промежуточную перезагрузку при переключении на проверенную навигацию с сохранением черновиков и состояния генерации. Измерить производительность и ресурсы, не обещать их по макету.
4. PostgreSQL и контролируемые миграции, приглашения, объектные права на приборы, корректировки/экспорт, ограничения частоты и эксплуатационное усиление.
5. Проверить managed-установку с двумя организациями и standalone с собственным IdP, backup/restore и обновление между двумя релизами.
6. Только после этих проверок рассматривать клиентский пилот. Снимать блокировку `APP_ENV=production` отдельным проверенным изменением, не переименованием окружения.

## Twenty

В runtime отсутствует. Должен оставаться опциональным. Будущая интеграция сохраняет полноценные UI/backend согласованной редакции с общим дизайном. React fixture не доказывает совместимость настоящего Twenty.

## GitHub и эксплуатация

Новая разработка размещается в `qlmsv/Verdeect`, каталог `platform/`, ветка `codex/platform-m0-foundation`. Существующие LibreChat, корневые Dockerfile и deployment workflows не меняются. Коммит/PR не равны развёртыванию сервиса. Проверки GitHub Actions необходимо читать отдельно: локальный успех не доказывает успешную установку зависимостей или сборку в CI.
