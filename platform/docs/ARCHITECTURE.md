# Архитектурные решения M0.1

Статус: начало реализации по ТЗ v0.2 и уточнениям заказчика. Документ не заменяет полное ТЗ. Дата переноса в GitHub: 2026-09-14.

## Зафиксированное направление

Используем контролируемый форк OpenWebUI, сохраняем готовый чат. Слева единый навбар, без iframe. Бизнес-логика, организации и права не переносятся внутрь чата. Поддерживаем отдельные репозитории модулей и будущую поставку SaaS/standalone одной кодовой базы.

OpenWebUI и новая платформа не заменяют существующий LibreChat в корне этого репозитория. Рабочая область текущей поставки: `platform/`. Каталог можно выделить в отдельный репозиторий позднее, без изменения HTTP-контрактов.

## Компоненты

- Platform API: организация установки, членство, назначения, аудит, серверные сессии и BFF для UI.
- Metering API: независимый процесс и БД приборов/показаний.
- Svelte UI: собственные страницы и внешний навбар вокруг штатных маршрутов OpenWebUI.
- UI SDK: mount, updateContext, canLeave, unmount, AbortSignal и ограниченное пространство маршрутов.
- Bootstrap: отдельный checkout закреплённого OpenWebUI с сохранением upstream-истории.

В M0.1 метаданные и бизнес-данные хранятся в раздельных SQLite БД. Это dev-решение, а не завершённая production-архитектура. PostgreSQL, миграции, автоматическое создание клиентских установок, backup/restore и локальный IdP standalone ещё предстоят.

## Идентичность и доступ

Личность связывается с issuer + subject, не только email. Назначение модуля проверяется сервером, навбар не является защитой. Платформенный администратор организации не становится автоматически техническим администратором OpenWebUI.

Платформа передаёт metering короткоживущий EdDSA-токен с конкретным пользователем, организацией, scope и audience. Сервис проверяет подпись и срок. Браузер не получает общий административный токен. После отзыва прав новые запросы BFF отклоняются; ранее выданное делегирование ограничено 30 секундами.

OIDC-контроллер подготовлен, но реальный совместный SSO с OpenWebUI не реализован. Выход сейчас завершает только платформенную сессию. Изменение chat-grant возвращает явную ошибку 409, а не ложное подтверждение отзыва.

## Upstream

`upstream.lock.json` закрепляет tag, commit и blob root layout. Применение изменений допускается только к чистому совместимому checkout. Сборщик переносит штатные маршруты в группу `(upstream)` без изменения их URL и добавляет собственные маршруты `/_platform/*`.

Тесты преобразования синтетические. Полный upstream ещё не собран. Переходы между приложениями пока выполняют document navigation с предупреждением. Обновления требуют review diff, сборки и регрессии, а не только замены версии.

## Будущий полный Twenty

Twenty не устанавливается и не загружается в первой версии. Позднее требуется полный штатный интерфейс и backend выбранной лицензированной редакции, а не урезанные карточки через API.

Архитектурный контракт не ограничен Svelte. React fixture проверяет направление подключения, но пока не является проверенной интеграцией Twenty. Предусмотреть адаптацию темы через общие токены, вложенные маршруты, модальные окна, очистку ресурсов, контроль несохранённых форм, сопоставление прав и отказ отдельного модуля без падения оболочки. Изменение организации требует уничтожения состояния предыдущей организации.

Сохранение полного Twenty проверяется отдельной матрицей штатных функций. Лицензирование SSO, брендинг и условия распространения проверяются перед внедрением. Не снимать лицензионные ограничения в коде.
